# Feature: Ruby-Style Pinyin Alignment

**Status:** ✅ Complete
**Last Updated:** 2026-01-13

---

## User Story
As a Chinese language learner, I want to see pinyin positioned directly under each Chinese character/word so that I can immediately associate characters with their pronunciation without scanning between separate lines.

## Background
Current layout displays pinyin as a continuous string below the Chinese text. While readable, this requires mental effort to match syllables to characters. Ruby-style alignment (like Japanese furigana) creates an immediate visual mapping that accelerates learning.

**Current:**
```
愛情的起點 都是最美的瞬間
ài qíng de qǐ diǎn dōu shì zuì měi de shùn jiān
```

**Proposed:**
```
愛情    的   起點    都是  最美   的   瞬間
àiqíng  de  qǐdiǎn  dōushì zuìměi de  shùnjiān
```

## Requirements

### Functional
- FR-001: System MUST display pinyin directly below its corresponding Chinese character(s)
- FR-002: System MUST preserve word groupings (multi-character words stay together with their pinyin)
- FR-003: System MUST handle punctuation gracefully (don't break layout on commas, periods, etc.)
- FR-004: System MUST fall back to current linear layout if alignment data is unavailable
- FR-005: System SHOULD use semantic HTML (`<ruby>` element) for accessibility where appropriate

### Non-Functional
- NFR-001: Layout must remain readable on mobile (min 320px viewport)
- NFR-002: Ruby text must not cause horizontal overflow on typical song lines
- NFR-003: Print styles must remain functional with aligned layout

## Acceptance Scenarios

**Scenario 1: Basic Aligned Display**
- GIVEN a lyric line with word-segmented pinyin data
- WHEN the page renders
- THEN pinyin appears centered below each Chinese word unit

**Scenario 2: Single Character Words**
- GIVEN words like 的, 是, 我 (single character)
- WHEN rendered
- THEN single syllable pinyin appears below single character

**Scenario 3: Multi-Character Words**
- GIVEN words like 愛情 (àiqíng), 瞬間 (shùnjiān)
- WHEN rendered
- THEN multi-syllable pinyin appears below grouped characters

**Scenario 4: Punctuation Handling**
- GIVEN Chinese text with punctuation (，。！？)
- WHEN rendered
- THEN punctuation does not have ruby text and doesn't break layout

**Scenario 5: Fallback for Legacy Data**
- GIVEN a song with only linear pinyin (not word-segmented)
- WHEN the page renders
- THEN current linear layout displays (graceful degradation)

**Scenario 6: Long Lines**
- GIVEN a line that would overflow horizontally with ruby spacing
- WHEN rendered
- THEN line wraps gracefully, keeping word units together

**Scenario 7: Mobile Display**
- GIVEN a mobile viewport (320-480px)
- WHEN viewing lyrics
- THEN ruby alignment remains readable without requiring horizontal scroll

## Data Format

**Current format (linear):**
```json
{
  "chinese": "愛情的起點 都是最美的瞬間",
  "pinyin": "ài qíng de qǐ diǎn dōu shì zuì měi de shùn jiān"
}
```

**Required format (word-segmented):**
```json
{
  "chinese": "愛情的起點 都是最美的瞬間",
  "pinyin": "ài qíng de qǐ diǎn dōu shì zuì měi de shùn jiān",
  "segments": [
    { "hanzi": "愛情", "pinyin": "àiqíng" },
    { "hanzi": "的", "pinyin": "de" },
    { "hanzi": "起點", "pinyin": "qǐdiǎn" },
    { "hanzi": " ", "pinyin": "" },
    { "hanzi": "都是", "pinyin": "dōushì" },
    { "hanzi": "最美", "pinyin": "zuìměi" },
    { "hanzi": "的", "pinyin": "de" },
    { "hanzi": "瞬間", "pinyin": "shùnjiān" }
  ]
}
```

## Segmentation Approach

**Decision:** LLM-based segmentation at data-prep time (NOT client-side library)

**Why:**
- LLM (Claude/Gemini) already processes lyrics for pinyin + translation
- Adding segmentation is a natural extension of that workflow
- LLM understands context (names, idioms, modern phrases) better than rule-based libraries
- Zero client-side dependency cost
- Data is explicit - what's in JSON is what renders

**Workflow integration:**
```
Chinese lyrics → Claude/Gemini → pinyin + translation + segments → songs.json
```

## Dependencies
- pinyin-pro library (already in project) - for any character-level fallback
- No new client-side dependencies required

## Constraints
- Must work with existing songs.json data (backwards compatible via fallback)
- Must not break existing features (sync highlighting, print, admin editor)
- Segmentation generated by LLM during add-song workflow

## Out of Scope
- Character-level stroke order or detailed definitions
- Audio pronunciation on hover

## Success Criteria
- SC-001: New songs can be added with ruby alignment that visually maps characters to pinyin
- SC-002: Existing songs continue to display correctly (no regression)
- SC-003: Learners report easier character-sound association (qualitative)
- SC-004: Mobile layout does not require horizontal scrolling
